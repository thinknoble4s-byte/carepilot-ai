Summary

The human safety path is largely built: Booked tap, send block, handover, Send to doctor, the doctor's gate, the instruction card with a 2-working-day deadline, the booking message and closure with a reason all exist (built for the Golden Path). What is missing is everything about understanding a reply: voice notes with audio, the Sarvam speech-to-text, translation and yes/no health flag with retry, and the "flag = no" path (AI proposal, hold, approve). Several working parts also need adjusting to UC2a's exact rules, names, wording and seed.

The biggest new pieces: an AI client layer for Sarvam (planned as Increment 4), voice-note storage and playback, a proposal and hold mechanism, a demo clock with time of day, and a new "after Use Case 1" seed.

Decisions needed before building

  1. Patient names. UC2a uses TP001 = Meena, TP004 = Kavita. Our UC1 seed has TP001 = Kavya Rao, TP002 = Meena Iyer. Recommend: rename to match UC2a (TP001 Meena …, TP004 Kavita …) and give TP002 another name.
  2. Send block for people. Today a person's send passes an open handover. UC2a allows only the acknowledgement and the doctor-instruction booking message. Recommend: switch to this template allow-list everywhere (it is stricter and safer); the Golden Path still works.
  3. Acknowledgement fallback vs Use Case 1's “no fallback”. Recommend: keep “no fallback” for every template except the acknowledgement, as REQ-07 says.
  4. Doctor screen. UC2a wants choice + Submit (disabled until chosen); the prototype has one-tap buttons. Recommend: follow UC2a (choice then Submit), keeping the prototype's look.
  5. G0 on instruction cards. Recommend: make REQ-13 permanent — G0 never runs on Doctor-requested cards in any data set.
  6. Voice clips. Native recordings are an open point. Recommend: generate stand-in clips HI-01 / HI-02 with Sarvam text-to-speech, clearly labelled synthetic, and swap in the native recordings when ready.
  7. Hold (REQ-17) depends on spec change v0.2 decision 10 (not signed off). Recommend: build it behind a setting, on for UC2a, so it can be removed without code changes.
  8. Running Sarvam. Real calls cost a small amount per message and need the database on for AWS demos; local tests use a fake Sarvam so the suite stays free and repeatable, with one opt-in live test.
  9. Audio storage on AWS. Needs a private S3 location (a small infrastructure change); locally, files on disk.
